# 二维转播式回放开发计划

## 目标与范围

以官方比赛转播的视觉层级为参考，制作全场俯视的二维数据回放：地图占主体、红蓝双方信息对称、时间与关键事件易读。保留场地几何和障碍物，通过图标、血量条、朝向和短轨迹表达比赛，不使用三维模型。

这是数据重建画面，不是真实视频。当前官方回放页面已检索，视频画面尚未逐帧核对；下述布局是待核对的设计方案，不宣称与官方 HUD 完全一致。

## 技术与目录

- Python 标准库 sqlite3，以 `mode=ro` 打开数据库；轻量本地 HTTP 服务提供比赛检索及单局数据。
- 前端使用 TypeScript、Canvas 2D 绘制地图和动画，HTML/CSS 绘制状态栏与控制栏。依赖及字体本地化，运行时无需外网。
- 动画使用 requestAnimationFrame 和统一回放时钟；时间由真实经过时间和倍速计算，避免按帧数累计。
- 按 game_id 加载单局，不把整个约 1.19 GB 数据库发送给浏览器。缓存机器人时间索引和事件索引；切局请求支持取消，缓存只保留有限局数。
- 文件归属：backend、frontend、assets、tests、cache 均位于 replay_2d。现有 SDR 播放器仅作为素材和经验参考。

## 界面设计

基准画布 1920×1080，优先兼容 1366×768。主画面保留 16:9 转播比例，地图按自身比例等比缩放，禁止拉伸。布局草案：

```text
┌────────────────────────────────────────────────────────────┐
│ 红方学校 / 基地血量   赛区·场次·局号 / 计时   蓝方学校 / 基地血量 │
├──────────┬────────────────────────────────────┬────────────┤
│ 红方状态  │                                    │ 蓝方状态    │
│ 英雄      │      官方战场底图 + 机器人标记       │ 英雄        │
│ 工程      │      全场主视角，地图不被面板遮挡     │ 工程        │
│ 步兵3/4   │                                    │ 步兵3/4     │
│ 哨兵/空中 │      关键事件字幕（靠底，短暂显示）   │ 哨兵/空中   │
│ 金币/前哨 │                                    │ 金币/前哨   │
├──────────┴────────────────────────────────────┴────────────┤
│ 事件标记时间轴       当前时刻 / 总时长                         │
│ 播放·逐秒·倍速       跟随 / 全场 / 图层      选中机器人摘要       │
└────────────────────────────────────────────────────────────┘
```

- 1920 宽度下顶部约 88 px、两侧各 200 px、底部约 120 px，其余空间给地图；小屏按可用高度调整。地图视口采用 contain，不为填满空白裁掉基地。
- 背景深灰蓝，面板轻微透明、细边框；红方暖红、蓝方亮蓝，同时显示阵营文字，避免只依赖颜色。金币用金色、事件用有限强调色。
- 中文优先使用 Windows 微软雅黑，数字采用等宽排列；不使用密集小字、强光晕、大面积渐变或持续闪烁。
- 双方机器人采用一致顺序，卡片显示类型、编号、血量及血量条；建筑独立显示。功率、热量等详细字段放入选中详情抽屉，默认不占地图面积。
- 同位置标记提供确定性的标签避让，选中对象置顶；全场视角默认短尾迹，可关闭。缩放跟随时始终保留“回到全场”。
- 比赛选择使用独立弹层，不长期占据画面；学校长名称允许两行或省略，并可查看全名。
- 不显示无法从数据证实的当前对局比分、实时击杀数、官方主状态或剩余发弹额度。最终胜方在回放结束显示，避免提前剧透。

## 数据与动画规则

1. 先实测时间步长、重复记录、NULL、坐标范围、单位、朝向单位和 robot_id 映射。数据库坐标不能直接套用无线协议的厘米单位；枪口朝向不能作为底盘朝向。
2. 核对地图版本：已有底图是规则 V2.2.0（20260807），数据库比赛发生于 5～6 月，须比较区域赛适用规则中的场地，再确定正式底图。
3. 建筑位置通过地图锚点固定绘制，不能把数据中 (0,0) 当成真实建筑位置。机器人坐标异常保留原值并标记，不能强行吸附到场内。
4. 正常相邻状态插值位置和最短角度旋转；血量、金币、热量按采样时刻阶跃更新。插值提高视觉平滑度，不提高数据时间精度。
5. 大位移、长间隔、缺失位置断开轨迹，禁止跨场飞行；阈值通过实际样本确定。拖动时间轴由目标时间重建状态，事件与轨迹不得残留。
6. NULL 与 0 分开显示；血量为 0 标记“零血量”，不能直接断言战亡。无人机行数与使用说明存在疑点，需实测活动判据后决定何时显示。
7. 事件按时间索引检索；同秒多条发弹可以合并为计数和短闪光，原始事件仍可查看。受击显示损失值，不推断攻击者或精确命中弹道。
8. 仅在有可靠字段时呈现增益类别及发生提示，不补造持续时间。默认无背景音乐、解说或重特效。
9. 时间轴明确显示“距开局时间”；可选倒计时按局时长减当前时刻计算，并标为回放倒计时，不等同于裁判系统阶段剩余时间。

## 分阶段开发与验收

### P0：数据与素材校准

输出数据审计报告、机器人编号映射、地图版本结论、坐标变换和素材来源台账。选取三个赛区各一局，并补充短局、缺失值多或轨迹异常的局。

验收：至少人工核对双方初始位置、基地/前哨站锚点及多个运动时刻；确定地图方向和单位；不通过则不得把地图配准称为准确。

### P1：视觉静态样板

制作真实数据驱动的单帧页面，完成顶部、双侧状态卡、地图标记和底部控制栏。先生成 1920×1080 和 1366×768 截图审查，再实现完整动画。

验收：两队信息一眼可分，长校名与大数字不溢出；地图不变形、基地不裁切；标签与血量条可读；常用操作无需滚动。与官方回放画面核对后记录相似点及主动简化项。

### P2：单局可播放回放

实现比赛选择、播放暂停、0.5/1/2/4 倍速、逐秒、拖动、全场与选中跟随、轨迹开关，以及机器人详细数据。

验收：任意时刻的血量/金币与数据库一致；连续拖动无旧状态污染；暂停画面稳定；播放至结束自动暂停；切局不混入上一局数据。

### P3：转播事件呈现

实现受击扣血、发弹闪光、事件字幕、关键事件时间轴和列表；详情支持查看原始事件。事件过密时聚合和限流。

验收：事件次数与单局 SQL 查询一致；同秒多事件不丢失；跳转不重放全部历史特效；无攻击方证据时不绘制攻击连线。

### P4：性能与交付

增加 Windows 启动脚本、离线依赖、配置说明、异常提示、缓存清理方式。在用户机器测量首次加载与缓存加载、连续播放帧率和内存。

目标：普通单局首次加载尽量不超过 3 秒，缓存后尽量不超过 1 秒；1920×1080、1 倍速尽量稳定 60 FPS，持续低于 30 FPS 时优化。上述是验收目标，尚未实测；不作当前性能承诺。

最小交付是 P0～P4 的交互回放器。自动导播、热力图和视频导出属于后续扩展，第一版不依赖它们。

## 验证重点

数据侧测试查询隔离、空值、时间定位及重复事件；前端测试插值、跨角度旋转、跳点和拖动重建。使用数据库样本作为独立预期值，不只测试实现内部逻辑。人工检查两个分辨率的截图和完整单局播放；记录浏览器版本与性能结果。
